# Чек-лист безопасности

В архиве хранятся личные данные: биография, здоровье, отношения в семье, голос и фотографии. Утечка голоса опаснее утечки пароля: его нельзя сменить, а по записям можно сделать голосовой клон. Поэтому правило одно: **данные видит только владелец аккаунта, и ни одна проверка не держится на честности браузера**.

Обозначения: ✅ сделано в коде · ⚙️ нужно включить владельцу сайта · 🔁 проверять регулярно · ⚠️ известное ограничение.

## 1. Вход и сессии

- ✅ Пароли — PBKDF2-SHA256, 100 000 итераций, соль 16 байт, сравнение за постоянное время (`src/lib/password.ts`).
- ✅ Пароль не короче 10 символов, не из списка самых частых, не содержит адрес почты, минимум 4 разных символа.
- ✅ Лимиты входа: 20 попыток за 15 минут с одного IP и 8 — на один адрес почты. Регистрация — 5 в час с IP.
- ✅ Одинаковый ответ на «нет такой почты», «неверный пароль» и «аккаунт через Google»; время ответа выравнивается фиктивным хэшем — по форме входа нельзя узнать, кто зарегистрирован.
- ✅ Honeypot-поле и Cloudflare Turnstile на формах входа и регистрации (Turnstile — при заданных ключах).
- ✅ Сессия — JWT HS256 в cookie `__Host-fm_session`: `HttpOnly`, `Secure`, `SameSite=Lax`, без `Domain`. Алгоритм, `iss` и `aud` закреплены, срок — 14 дней.
- ✅ Каждый запрос сверяет версию сессии с базой: «Выйти на всех устройствах» и удаление аккаунта отзывают все токены сразу, а не через 14 дней.
- ✅ Google: Authorization Code + PKCE, `state` в подписанной cookie на 10 минут, проверка подписи, `iss`, `aud` и `email_verified`. Привязка по почте сбрасывает пароль и все прежние сессии.
- ✅ Перенаправление после входа — только на пути этого сайта (`isSafeNext`), открытого редиректа нет.
- ⚙️ `AUTH_SECRET` — случайная строка не короче 32 символов (`openssl rand -base64 48`); в продакшене приложение без неё не запустится. Хранить только как секрет Wrangler.
- 🔁 Смена `AUTH_SECRET` выводит из всех аккаунтов — делать при любом подозрении на утечку.
- ⚠️ Почта при регистрации не подтверждается и сброса пароля нет — для этого нужен почтовый сервис. До его подключения советуйте входить через Google.
- ⚠️ Двухфакторной защиты для пользователей нет; вход через Google наследует 2FA аккаунта Google.

## 2. Доступ к данным

- ✅ Любой запрос к архиву проходит `assertPersonAccess`: профиль ищется по паре «id + владелец». Чужой id даёт 404, а не 403 — существование чужих архивов не раскрывается.
- ✅ Вложенные объекты (записи, воспоминания, теги, избранное) дополнительно проверяются на принадлежность этому профилю.
- ✅ Страницы `/app/**` закрыты middleware и повторно проверяют владельца на сервере.
- ✅ R2 приватный: файлы отдаются только через API после проверки владельца, прямых ссылок нет.
- ✅ Ответы API: `Cache-Control: private, no-store` и `X-Robots-Tag: noindex` — личные данные не оседают в кэше браузера, прокси и поисковиков. Аудио и фото тоже не кэшируются.
- ✅ `robots.txt` и `noindex` закрывают архивы, вход и API от индексации.
- ✅ Пользователь сам удаляет аккаунт: сначала стираются файлы в R2, затем записи в базе (каскадом). Для аккаунта с паролем требуется пароль — одной украденной cookie недостаточно.

## 3. Формы и входные данные

- ✅ Все тела запросов проходят zod-схемы с ограничением длины каждого поля и количества элементов.
- ✅ Ответы на тесты фильтруются по списку известных вопросов и допустимых значений, результат считается только на сервере.
- ✅ Неизвестные `questionId` и чужие `memoryId` отклоняются.
- ✅ Загружаемые файлы проверяются по первым байтам (WAV, MP3, JPG, PNG, WebP), а не по имени и MIME от браузера; есть лимиты размера.
- ✅ CSRF: изменяющие запросы проверяют `Origin` и `Sec-Fetch-Site`, плюс `SameSite=Lax`.
- ✅ SQL-инъекции исключены: только Prisma с параметрами, сырого SQL с пользовательскими данными нет.
- ✅ XSS: React экранирует вывод; единственный `dangerouslySetInnerHTML` — статический скрипт темы.
- ✅ Лимиты: 1200 изменений за 10 минут с одного IP, 20 новых архивов в час, загрузка 200 записей в час, расшифровка 30 в час. Счётчики атомарные, хранятся в D1 в виде SHA-256 (IP и почта открытым текстом не сохраняются).
- ✅ Квоты: 30 архивов на аккаунт, 3000 воспоминаний, 3000 элементов избранного и 2000 записей на архив.
- ✅ Ошибки сервера отдаются клиенту общим текстом; подробности — только в логе Workers. В интерфейсе нет имён переменных окружения и путей к коду.

## 4. Заголовки и браузер

- ✅ CSP: `default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`, `upgrade-insecure-requests`.
- ✅ HSTS на год, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`, `Permissions-Policy` (микрофон — только этому сайту, камера и геолокация запрещены).
- ⚠️ В CSP разрешены inline-скрипты (скрипт темы и данные гидратации Next.js). Nonce сделал бы все страницы динамическими; риск закрыт отсутствием небезопасного HTML.
- ⚠️ Режим «без регистрации» хранит данные в IndexedDB браузера без шифрования: любой, у кого есть доступ к этому устройству и профилю браузера, их увидит. Об этом сказано на экране выбора хранения.

## 5. Инфраструктура (Cloudflare)

- ⚙️ Двухфакторная аутентификация на аккаунтах Cloudflare, Google Cloud и GitHub — кто управляет ими, тот управляет базой.
- ⚙️ API-токены CI — с минимальными правами (*Edit Cloudflare Workers*, только ваш аккаунт). Global API Key не использовать.
- ⚙️ Turnstile: создать виджет, задать `TURNSTILE_SITE_KEY` и секрет `TURNSTILE_SECRET_KEY`.
- ⚙️ `CONTACT_EMAIL` — адрес для обращений по данным (показывается в политике конфиденциальности).
- ✅ У D1 нет публичного адреса: доступ только из Worker'а или через API Cloudflare с токеном. Данные D1 и R2 шифруются Cloudflare на диске.
- ✅ Демо-аккаунт с известным паролем создаётся только локальным `npm run db:seed`, в продакшен-базу он не попадает.
- 🔁 Резервные копии: Time Travel D1 (7 дней на Free) и `wrangler d1 export` раз в месяц. Файл дампа содержит личные данные — хранить зашифрованным.
- 🔁 Раз в месяц: `npm audit --omit=dev`, обновление Next.js и Prisma, просмотр `wrangler secret list` и логов Workers на всплески 401/403/429.

## 6. Третьи стороны

- ✅ Данные уходят наружу только по явному действию: расшифровка (аудио — в OpenAI). Аналитики и рекламы нет.
- ⚠️ Шрифты загружаются с Google Fonts: Google видит IP посетителя. Чтобы исключить и это, шрифты можно положить в `public/`.

## Проверка перед релизом

1. `npm run lint && npm run typecheck`.
2. Без cookie: `GET /api/persons` → 401; с чужим id профиля → 404.
3. `POST` с `Origin: https://evil.example` → 403.
4. Слабый пароль при регистрации → 400; 9 неверных входов подряд на одну почту → 429.
5. «Выйти на всех устройствах», затем запрос со старой cookie → 401.
6. Ответы API содержат `Cache-Control: private, no-store`.
7. Загрузка HTML-файла под видом WAV или фото → 400.
8. Удаление аккаунта: после него вход с теми же данными не работает, файлов в R2 с ключом `persons/<id>/` не осталось.
